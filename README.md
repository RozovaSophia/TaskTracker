## О проекте
Проблема:
Во многих компаниях сотрудники и руководители сталкиваются с отсутствием прозрачности в задачах. Менеджеры не видят реальную загрузку команды, а сотрудники используют разрозненные инструменты (мессенджеры, почту) для учета задач. Это приводит к срыву дедлайнов и хаосу в коммуникации.

Решение:
Данный проект представляет собой API для трекера задач, который решает проблему учета поручений. Система позволяет:

Руководителям создавать задачи, назначать ответственных и отслеживать статус выполнения.

Сотрудникам видеть актуальный список задач, менять их статус и отчитываться о выполнении в едином окне.

## Бизнес-ценность
Внедрение данного решения позволяет количественно повлиять на эффективность работы отдела:

Экономия времени: Сокращение времени на ежедневные планерки по обсуждению статуса задач до 15 минут в день (экономия более 5 часов в месяц на одного руководителя).

Снижение операционных затрат: Исключение потери задач из-за "человеческого фактора" снижает риск штрафов за несвоевременное выполнение работы.

Рост производительности: Визуализация задач и прозрачность ответственности повышает личную эффективность сотрудников на 15-20% .

Масштабируемость: Благодаря контейнеризации (Docker) система легко разворачивается на новых серверах при расширении штата.

## Стек технологий
Язык: Python 3.13.3

Бэкенд-фреймворк: Django 6.0.2

API: Django REST Framework (DRF)

База данных: PostgreSQL (или SQLite для разработки)

Аутентификация: JWT-токены (Simple JWT / Djoser)

Документация: drf-yasg / drf-spectacular (автогенерация Swagger/ReDoc)

Контейнеризация: Docker, Docker Compose

Система контроля версий: Git (GitHub)

Тестирование: Unittest / pytest, coverage.py

## Функционал
Ролевая модель: Разделение прав на Администратора (Manager) и Сотрудника (Employee).

Управление задачами: Полный набор CRUD-операций для задач.

Статусы задач: Жизненный цикл задачи (К выполнению / В работе / Выполнена).

Назначение ответственных: Возможность привязать задачу к конкретному сотруднику.

API: Полностью функционирующий REST API.

Документация в реальном времени: Интерактивная документация по адресу /swagger/.

Готовность к деплою: Запуск в одну команду благодаря Docker.

## Быстрый старт
Инструкция по запуску проекта локально.

Требования
Установленные Docker и Docker Compose (рекомендуемый способ)

Или Python 3.13.3+ и Poetry/pip

Запуск через Docker (рекомендуется)
Клонируйте репозиторий

sh
git clone https://github.com/[ТВОЙ_НИК]/[ИМЯ_РЕПОЗИТОРИЯ].git
cd TaskTracker
Создайте файл с переменными окружения
Создайте файл .env в корне проекта (можно скопировать .env.example).

dotenv
DEBUG=True
SECRET_KEY=ваш-секретный-ключ
DB_NAME=tasktracker_db
DB_USER=postgres
DB_PASSWORD=пароль-бд
DB_HOST=db
Соберите и запустите контейнеры

sh
docker-compose up --build
Примените миграции (в отдельном терминале)

sh
docker-compose exec web python manage.py migrate
Создайте суперпользователя

sh
docker-compose exec web python manage.py createsuperuser
После запуска API будет доступно по адресу: http://localhost:8000/api/.
